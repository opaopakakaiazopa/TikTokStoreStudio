# Store Studio

Локальная программа для создания коротких вертикальных роликов с русским интерфейсом. Видео сохраняются на компьютере вместе с описаниями. Подключения аккаунтов и публикации в TikTok нет.

## Запуск

На этом компьютере окружение и FFmpeg уже установлены.

1. Откройте `Запустить Studio.bat`.
2. Панель откроется по адресу http://127.0.0.1:8765.
3. Оставьте окно запуска открытым. Для остановки нажмите Ctrl+C в нём либо «Завершить работу Studio» внизу панели.

Если программа уже запущена, повторный запуск откроет существующую панель. Для доступа к материалам интернет не требуется.

Для установки заново нужен Python 3.11 или новее и интернет: запустите `Установить.bat`. Скрипт создаёт `.venv`, ставит библиотеки из `requirements.txt`, скачивает переносимые FFmpeg и ffprobe с gyan.dev в `tools/bin`. Системный PATH не изменяется. Если оба инструмента уже доступны в PATH, скачивание не требуется.

## Первая партия

1. В «Материалах» добавьте исходное видео и музыку. Большое видео удобнее подключить кнопкой «Подключить по пути»: второй копии не будет.
2. В «Текстах и описаниях» добавьте рекламные тексты; разделяйте варианты пустой строкой. Укажите не менее пяти разных хештегов и настоящий адрес магазина в описании.
3. На экране «Создать видео» выберите материалы. По умолчанию получится пять роликов по 13–15 секунд, 1080 × 1920, с белой надписью и чёрной обводкой.
4. Настройте кадрирование, шрифт и громкость. Предпросмотр оформления обновляется автоматически. Надпись можно перетаскивать мышью/пальцем или двигать стрелками после выделения. Кнопка ▶ воспроизводит короткий фрагмент видеофона без звука, ползунок позволяет перематывать его. В настройках предпросмотра можно выбрать другой исходник, участок и вариант текста. Случайные фрагменты будущей партии показываются отдельно после её подготовки.
5. Нажмите «Подготовить партию». Проверьте выбранные фрагменты, надписи и описания на экране «Твои видео». До запуска можно поменять надпись или пересоздать выбор для отдельного задания.
6. Нажмите «Создать 5 видео». Очередь соберёт их параллельно: по умолчанию по два ролика, с кодированием NVIDIA при доступности. Готовые ролики можно воспроизвести, скачать отдельно либо получить ZIP всей готовой части партии.

Обычная надпись на видео и описание публикации — разные тексты. Описание содержит шаблон магазина и пять случайных уникальных хештегов.

## Настройки и результаты

- Оформление и параметры сохраняются автоматически. Кнопка «Сохранить» позволяет сразу проверить и сохранить значения.
- Пресеты сохраняют количество, длительность, оформление, кадрирование и звук. Тексты, хештеги и папка результата остаются текущими.
- Внутри партии фрагменты не пересекаются, пока хватает исходника. При нехватке можно уменьшить количество/длительность, добавить видео или явно разрешить повторы.
- При недостатке рекламных текстов они повторяются с предупреждением. При недостатке тегов подготовка не запускается.
- Направляющие безопасной области служат подсказкой. Надпись можно двигать по всему кадру; галочка «Удерживать всю надпись внутри кадра» предотвращает обрезку. Шрифт автоматически уменьшается до указанного минимума; слишком длинный текст необходимо сократить.
- Ползунок звука исходника установлен на 0%. Музыка по умолчанию — 60%. Можно смешивать обе дорожки. Если музыка короче ролика, включите её повтор либо выберите другую дорожку.
- «Приостановить очередь» заканчивает уже начатые ролики и задерживает остальные. «Отменить» может остановить и текущую сборку. Незавершённый MP4 не считается готовым.
- При нормальном закрытии программы текущая сборка прерывается. После запуска ожидающие и прерванные задания требуют кнопки «Возобновить»/«Повторить». Готовые результаты сохраняются.
- Повтор после ошибки использует тот же фрагмент и оформление. «Пересоздать выбор» до запуска меняет подбор, учитывая остальные задания партии.

По умолчанию готовые файлы находятся в `output/videos/<дата_партии>/`: MP4, TXT-описания и `manifest.json` с параметрами. Папку можно изменить в настройках. Изменение относится к новым партиям.

## Материалы и данные

При обычной загрузке программа сохраняет копию материала в `assets`. Подключение по пути использует исходный файл без копирования. Удаление записи из библиотеки оставляет файл на диске. Уже подготовленные задания сохраняют путь к своим материалам.

Внешние исходники нельзя перемещать до окончания сборки. При потере доступа подключите файл заново и подготовьте новую партию либо верните исходный файл по сохранённому пути, чтобы повторить старое задание.

Настройки, библиотека и история лежат в `data/studio.db`. Для резервной копии остановите приложение и скопируйте папки `data`, `assets` и нужные результаты. Внешние исходники копируются отдельно.

Кнопка очистки в настройках удаляет только временные файлы старше суток, не нужные незавершённым заданиям, и устаревшие кадры живого предпросмотра. Готовые ролики и материалы она не удаляет.

## Ограничения первой версии

- Панель доступна только на текущем компьютере по 127.0.0.1. Сервер не открыт в локальную сеть или интернет.
- Все новые ролики экспортируются в HDR10: MP4, HEVC Main 10, yuv420p10le, PQ / SMPTE ST 2084, BT.2020, AAC, 30 кадров/с. Для HDR-источников сохраняется диапазон яркости; SDR преобразуется в HDR-контейнер без восстановления отсутствующих деталей. Белая надпись соответствует примерно 203 нитам.
- Видеофон и готовые видео внутри браузера показываются в отдельной SDR-копии для совместимости. Кнопки скачивания и ZIP выдают оригиналы HDR10. Ранее созданные SDR-ролики сохраняют прежний формат. HDR-экспорт обычно занимает больше времени, чем прежний H.264.
- Защищённые, повреждённые или не поддерживаемые FFmpeg файлы могут требовать предварительного преобразования.
- История уменьшает число повторов исходных отрезков, но не гарантирует визуальную уникальность кадров.
- Требуется свободное место для исходников, результата и архива при скачивании партии.

## Проверки

`scripts/check_pipeline.py` запускает отдельную копию приложения на порту 8766 и создаёт временные синтетические материалы. Он проверяет подготовку и сборку пяти роликов, описания, очередь, паузу, отмену, повторы, экспорт и сохранение состояния. При успехе временная рабочая папка удаляется, отчёт остаётся в `docs/check-results.json`; при ошибке сохраняется для диагностики.

Команда: `.venv\Scripts\python.exe scripts\check_pipeline.py`.

Дополнительная проверка `scripts/check_hdr_preview.py` проверяет цветовые параметры файла, реальные значения яркости после SDR→HDR и HDR→HDR, яркость надписей, живые слои с реальными шрифтами и браузерные копии. Отчёт: `docs/hdr-check-results.json`. Журналы ошибок находятся в `logs`.

## Ускорение на GTX 1650

В «Настройках → Скорость сборки» выбираются кодирование (Авто / NVIDIA NVENC / CPU) и число одновременно обрабатываемых роликов (1–3). По умолчанию — Авто и 2 ролика. При запуске проверяется реальная доступность HEVC Main10 в установленном драйвере. Если ускорение недоступно или кодирование NVIDIA завершилось ошибкой, используется CPU с тем же фрагментом, музыкой и оформлением.

Новая настройка применяется к ожидающим заданиям при их запуске, включая ранее подготовленные партии. При уменьшении параллельности уже запущенные задания продолжают работу. Ускорение относится к кодированию; преобразование цвета, текст и совместимая копия для браузера используют CPU. Поэтому выигрыш зависит от исходника, разрешения и процессора. На GTX 1650 с 4 ГБ стоит начинать с двух одновременных роликов; три могут оказаться медленнее.

В карточке ролика виден фактический кодировщик и переход на CPU, если он потребовался. После завершения отображается время сборки с подготовкой просмотра. Итог всегда HDR10. Для NVENC используется небольшой кэш HDR-метаданных в `data/encoder_cache`; его первый файл создаётся один раз для каждого разрешения и профиля яркости.

## Залив в TikTok

В отдельном разделе «Залив в TikTok» можно выбрать готовые ролики Studio или добавить MP4, назначить каждому один аккаунт и запустить отправку. Поддерживаются до пяти аккаунтов. Кнопка «Распределить по очереди» назначает выбранные видео отмеченным аккаунтам по кругу; назначения можно поменять вручную. Видимость выбирается для каждого ролика из вариантов, доступных его аккаунту. Описание, рекламные отметки, комментарии, дуэты и сшивание настраиваются кнопкой «Описание и параметры».

Между началом двух отправок выдерживается минимум 40 секунд глобально для всей очереди. При долгой передаче интервал увеличивается. TikTok отдельно обрабатывает видео: статус «Опубликовано» ставится после ответа PUBLISH_COMPLETE, а не после передачи байтов. Пауза задерживает следующие отправки; уже начатая заканчивается и проверяется. После перезапуска очередь ожидает «Продолжить очередь»; подтверждение уже принятых публикаций проверяется автоматически.

История хранится в studio.db и исключает повтор одного файла на любом аккаунте по SHA-256. Переименование или копирование не создаёт новый ролик для очереди. Ограничение закреплено уникальным индексом SQLite; повторный клик по запуску не создаёт дублей. При обрыве связи после создания публикации сохраняется её publish_id и проверяется та же отправка. Если результат создания неизвестен и publish_id не получен, задача получает статус «Результат не подтверждён» и повтор блокируется. Подтверждённую ошибку можно повторить вручную.

История относится к отправкам из этой Studio. Видео, уже опубликованные вручную или другой программой, необходимо пометить действием «Уже выкладывалось», выбрав соответствующий аккаунт. Это ручная отметка в истории, без обращения к TikTok. Программа не сверяет весь контент аккаунтов с файлами на диске. Изменённый файл с другими байтами считается новым содержимым.

### Первое подключение

1. В «Подключение приложения TikTok» сохраните Client key и Client secret своего приложения с доступом video.publish.
2. Для Desktop Login Kit адрес возврата — `http://127.0.0.1:8765/api/publishing/oauth/callback`.
3. Добавьте аккаунт с понятным названием. При необходимости укажите постоянный прокси HTTP, HTTPS или SOCKS5, например `http://user:password@host:port`.
4. Нажмите «Подключить TikTok» и завершите вход в открывшемся окне. Адрес страницы должен использовать тот же 127.0.0.1, что и Studio, чтобы сохранить привязку авторизации к браузеру.
5. Выберите видео, назначьте аккаунты и видимость, проверьте описания и нажмите «Начать залив».

Токены, Client secret и пароли прокси шифруются Windows DPAPI для текущей учётной записи Windows. Они не возвращаются в состояние интерфейса и не записываются в журналы HTTP. API-запросы, обновление токенов и передача видео используют прокси соответствующего аккаунта; открытое окно входа использует сетевые настройки браузера. При настройке прокси пустое поле сохраняет прежний адрес; отдельная галочка удаляет его. Автоматической ротации нет.

Интеграция использует [TikTok Desktop OAuth](https://developers.tiktok.com/docs/en/login-kit-desktop), [Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post) и [проверку статуса](https://developers.tiktok.com/docs/en/content-posting-api-reference-get-video-status). Возможность публичной публикации определяется доступом приложения и аккаунта на стороне TikTok. Выбранный готовый HDR-файл передаётся без перекодирования; сохранение HDR после обработки TikTok зависит от платформы.

Офлайн-проверка: `.venv\Scripts\python.exe scripts\check_publishing.py`. Она использует отдельную временную базу и имитацию ответов TikTok; реальных публикаций не делает. Проверяются интервалы, адресаты, шифрование, обновление токенов, запрет дублей, обрывы связи, перезапуск и локальные API. Отчёт — `docs/publishing-check-results.json`. Реальная публикация требует подключения приложения и аккаунтов; до этого она не проверена.

### Залив одной кнопкой

На экране готовых видео и в разделе залива есть кнопка «Залить новые видео». Она сама обновляет библиотеку из готовых результатов Studio, выбирает доступные файлы без активной/подтверждённой отправки, распределяет их по кругу и запускает очередь. Вручную отмечать ролики и назначать получателей при каждом запуске не требуется. Описания берутся из готовых роликов. Уже отправленные и ожидающие подтверждения видео исключаются; отсутствие новых видео не создаёт дублей. При наличии остановленной очереди эта же кнопка продолжает её.

Один раз для каждого нужного аккаунта откройте «Настроить», включите «Использовать этот аккаунт для залива одной кнопкой» и выберите видимость. Там же задаются рекламная отметка и признак ИИ-контента. Параметры сохраняются в базе, а выбранные получатели и видимость показываются перед быстрым запуском. При отключении аккаунта или изменении доступной видимости быстрый запуск требует обновить его настройку. Неподходящие по описанию или длительности файлы пропускаются с указанием их количества.

Первичная настройка Client key/secret и авторизация TikTok необходимы и в этом режиме. Она не повторяется при каждом запуске, пока авторизация действительна. После закрытия Studio потребуется снова запустить программу и нажать кнопку продолжения/залива; отправка новых роликов при запуске программы сама не начинается.

## Редактор надписи

В «Создать видео → Надпись на видео» настраиваются межстрочный интервал, расстояние между буквами, дополнительный отступ после ручного переноса строки, выравнивание строк, ширина блока, поворот и непрозрачность. Шрифт, цвета и обводка сохраняются вместе с оформлением в пресетах. Значения в px относятся к 1080p и пропорционально уменьшаются для 720p.

Положение центра задаётся в диапазоне 0–100% по обеим осям. Старое ограничение правого края на 84% снято. Направляющие TikTok показываются для ориентира. Если включено удержание в кадре, учитываются реальные размеры надписи после поворота; выключение позволяет частично выводить текст за край. Ползунки дублируются числовыми полями для точной настройки.

Выбранный вариант текста редактируется прямо под предпросмотром. Надпись перетаскивается мышью или пальцем; кнопки стрелок и клавиши при выделенной надписи двигают её на указанный шаг в пикселях выходного кадра. Shift увеличивает шаг в десять раз, Alt уменьшает в десять раз. Есть центрирование по отдельным осям и сброс оформления. Изменения оформления применяются к новым подготавливаемым партиям; уже готовые файлы не перекодируются автоматически.

Предпросмотр, кадры партии и итоговый рендер используют общий Pillow-рендерер из typography.py. Его проверки: scripts/check_editor.py, docs/editor-check-results.json. Примеры оформления: docs/editor-examples.png. HDR-конвейер дополнительно проверен с межбуквенным интервалом, выравниванием и поворотом в scripts/check_hdr_preview.py.

## Плавная шкала ожидания

В «Создать видео → Шкала ожидания» включается верхняя полоска с произвольной подписью снизу. Можно менять её ширину, отступ сверху, толщину, цвет дорожки и заполнения, размер/цвет текста и расстояние от полоски до подписи. Шрифт берётся из оформления основной надписи. Подпись переносится до трёх строк и при необходимости уменьшается. Есть заготовки фраз и отдельный проигрыватель анимации с перемоткой.

Финиш фиксирован на 80% фактической длительности каждого ролика. Формула заполнения: `1 − (1 − min(t / (0.8 × duration), 1)) ^ easing`; параметр замедления всегда больше 1, поэтому старт быстрее завершения. До отметки 80% хотя бы последний пиксель остаётся незаполненным; после неё шкала полная до конца. В видео 30 кадров/с завершение появляется на первом кадре, соответствующем 80% времени или следующем за ним. Интервал длительности партии не влияет на правило: каждый ролик получает свой момент завершения.

В предпросмотре шкала синхронизируется с воспроизводимым фрагментом фона. Отдельная кнопка «Показать анимацию» использует среднюю выбранную длительность; можно проверить шкалу и без исходника. Оформление сохраняется в пресетах и новых партиях. Уже подготовленные/готовые ролики автоматически не изменяются.

В финальный HDR-файл шкала и подпись добавляются отдельным слоем в 10-битном PQ, как и основная надпись. Анимируется только небольшая полоска, чтобы ограничить нагрузку на CPU. Для NVENC отдельно сохраняются статические HDR-метаданные; видео и звук обрабатываются независимыми графами FFmpeg. Проверки: scripts/check_progress.py, docs/progress-check-results.json; проверены реальные кадры и экспорт через CPU/NVIDIA.
